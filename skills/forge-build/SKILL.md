# FORGE Build

1. Inspect the repository before proposing a stack or editing.
2. Convert the request into requirements, constraints, non-goals, and acceptance criteria.
3. Use forge_create_plan as a baseline, then tailor it to the actual repository.
4. Implement the smallest end-to-end vertical slice first.
5. Read files before editing; use workspace-scoped FORGE tools.
6. Run relevant tests and report their actual status.
7. Summarize changed files, checks run, limitations, and next steps.

Never claim a build, test, deployment, or visual match succeeded unless verified. Ask before destructive changes, deployments, spending, or access-control changes.
